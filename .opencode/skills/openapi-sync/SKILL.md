## What I do

Fetch and inspect the OpenAPI spec generated by the running FastAPI server. Market Data Hub has no auto-generated TypeScript client — this skill is for verifying the spec is correct, documenting the current API surface, and catching schema drift after model changes.

## When to use me

- After adding or modifying a FastAPI route (`app/api/routes_*.py`)
- After changing a Pydantic model (`app/models/`)
- When verifying a response model matches what the route actually returns
- To generate a snapshot of the current API for documentation or external clients

## Prerequisites

The FastAPI server must be running:

```bash
# HTTP server only (dev)
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

# Or both servers
python -m app.main
```

## Fetch the spec

```bash
# Pretty-print the full spec
curl http://localhost:8000/openapi.json | python -m json.tool

# Save to file
curl http://localhost:8000/openapi.json > openapi.json

# Check a specific endpoint
curl http://localhost:8000/openapi.json | python -m json.tool | grep -A 20 '"/prices/'
```

## Interactive docs

```
http://localhost:8000/docs      # Swagger UI
http://localhost:8000/redoc     # ReDoc
```

Use these to manually verify request/response shapes after model changes.

## What to check after route/model changes

1. **Response model present** — every route has a `response_model=` set
2. **Decimal fields** — financial values must appear as `string` type in JSON Schema (Pydantic serializes `Decimal` as string)
3. **Optional fields** — nullable fields have `"anyOf": [{"type": "..."}, {"type": "null"}]`
4. **Error responses** — `AppError` subclasses map to correct HTTP status codes via the exception handler in `app/main.py`
5. **Query params documented** — all `Query()` params have `description=` set

## Architecture note

FastAPI auto-generates `/openapi.json` at runtime from:
- Route decorator annotations (`response_model`, `status_code`, `tags`, `summary`)
- Pydantic schema fields (name, type, `Field(description=...)`)

There is no separate code-gen step and no generated client to commit — the spec is always live from the running server.

## If spec looks wrong

- Missing route → check router is registered in `app/main.py` with `app.include_router(...)`
- Wrong response type → check `response_model=` on the route decorator
- Missing field → ensure the Pydantic model field has a type annotation
- Decimal shows as number → ensure the model uses `Decimal`, not `float`
